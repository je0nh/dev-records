# 테스트 관리

테스트 코드는 프로젝트와 함께 버전 관리한다. 매 실행의 로그나 결과 JSON을 테스트 코드 폴더에 쌓지 않는다.

| 파일 | 역할 |
|---|---|
| test_cli.py | 기본 CLI 흐름·실패·중단·동시성 및 공통 fixture |
| test_extra.py | Git 정보·경로 검증·플러그인·uv 통합 검증 |
| trace_cli.py | subprocess 커버리지 측정 보조 도구 |

실행 방법은 [검증 가이드](../docs/TESTING.md)를 따른다.

## 확장 기준

새 테스트는 날짜/작업 ID 대신 검증하는 기능 기준으로 배치한다. 같은 보장을 검증하는 테스트는 합치거나 데이터 기반으로 구성하되 서로 다른 오류 경로는 보존한다. 현재처럼 작은 규모에서는 평면 구조를 유지한다. Git 동기화 같은 기능이 추가되면 test_sync.py처럼 기능 단위로 파일을 추가하고, 공통 fixture가 커지면 support.py로 분리한다. unittest discover로 발견되는지 함께 검증한다.

임시 데이터는 TemporaryDirectory를 사용하고 정리한다. 고정 fixture는 작고 민감정보 없는 입력만 보관한다. 큰 데이터·빌드 산출물·실행별 보고서는 외부 기록 저장소나 CI artifact에 둔다. 제거된 기능의 테스트와 실제 중복은 정리하되, 이미 고친 버그의 회귀 테스트는 관련 기능이 유지되는 동안 보존한다.
