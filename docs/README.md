# 문서 구성과 보관 기준

현재 문서는 아래 파일을 갱신한다. 새 작업이나 테스트 실행마다 별도 문서를 만들지 않는다.

| 문서 | 용도 |
|---|---|
| [기획](PLAN.md) | 구현 범위와 다음 단계 |
| [CLI 명세](CLI.md) | 현재 명령과 데이터 계약 |
| [설계](DESIGN.md) | 구조와 중요한 결정 및 이유 |
| [플러그인](PLUGIN.md) | 패키징과 사용 절차 |
| [검증](TESTING.md) | 실행 방법과 검증 범위 |
| [초기 인수인계](archive/DEV_RECORDS_HANDOFF.md) | 보관된 개발 시작 자료 |
| [초기 검증](archive/INITIAL_VALIDATION.md) | 보관된 MVP 검증 이력 |

## 저장 위치

| 종류 | 위치와 관리 방법 |
|---|---|
| 소스·테스트 코드·현재 문서·uv.lock | 도구 Git 저장소에 커밋 |
| 중요한 설계 결정 | 우선 DESIGN.md에 추가. 커지면 decisions/로 분리 |
| 더 이상 현재가 아닌 중요한 문서 | archive/에 당시 기준임을 표시해 보관 |
| 작업 기획·구현 기록·실행 JSON·원본 로그 | 도구 소스 밖의 사용자 기록 저장소 |
| CI 실행 로그·커버리지 보고서·빌드 산출물 | CI artifact 또는 로컬 생성물. 소스에 커밋하지 않음 |
| 작은 고정 테스트 fixture | 재현에 필요한 경우 tests/fixtures/에 커밋 |
| .venv·캐시·로컬 환경 설정 | .gitignore로 제외 |

archive/는 매 실행의 로그를 모으는 곳이 아니다. 일반 변경 이력은 Git commit/PR로 추적하고, 보관 가치가 있는 전환 자료만 남긴다. 사용자 기록의 GitHub 백업은 별도 기록 저장소의 동기화로 제공할 예정이며 아직 구현되지 않았다.

문서가 오래되면 기존 내용을 갱신하고, 중복 설명은 대표 문서로 연결한다. tests/는 기능이나 회귀를 검증하는 코드를 유지하며 파일 수나 경과 시간만으로 테스트를 삭제하지 않는다.
