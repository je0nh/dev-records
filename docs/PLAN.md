# 기획 · 0.1 로컬 MVP

## 확정된 목표
개발 기획 → 구현 → 실제 검증을 프로젝트별로 보관한다. 도구 소스와 사용자 기록은 분리한다. 실패와 재실행을 보존하며 원격 확인 없이 업로드 완료라 쓰지 않는다.

## 지원 범위

CLI는 OS별 실행 제한을 두지 않는다. Windows에서도 공통 기능을 사용할 수 있게 유지하고 POSIX 전용 테스트만 조건부 실행한다. Windows 전용 프로세스 트리 종료 기능은 이번 범위에 추가하지 않는다. 접속하는 PC의 OS가 아니라 CLI가 실제 실행되는 호스트의 환경을 기준으로 명령을 선택한다. macOS 테스트 성공과 Linux 실환경 검증을 구분한다. Linux에서 CLI·셸 래퍼·프로세스 종료·임시 파일 정리를 검증한 뒤 지원 결과를 보고한다.

## 이번 구현과 완료 기준
- Python 3.11+ 표준 라이브러리 CLI; uv가 관리하는 .venv에서 모듈/번들 스크립트 실행.
- 명시적인 외부 기록 루트 초기화, 프로젝트 등록, 독립 작업 ID와 문서 생성.
- argv 그대로 실행, cwd 선택, stdout/stderr 원본 파일, 시각/소요 시간/종료 코드/Git/실행기 환경 수집.
- 성공·실패·실행 불가·시간 초과·SIGINT/SIGTERM 중단을 구분. 강제 종료 시 running 기록을 보존하며 성공으로 추정하지 않음.
- 공백/한글 경로, 비 Git 프로젝트, 중복/경로 이탈 방지, 동시 작업/실행, 두 다른 명령의 프로젝트 흐름을 자동 검증.
- 개인 플러그인 manifest + Skill + 실행 스크립트 제공. 실제 앱 설치는 다음 단계.

## 다음 단계 제안 (아직 구현하지 않음)
Git sync를 별도 모듈로 추가한다. task 범위 staging, 인덱스 격리, 직렬 commit/push, 재시도, 원격 확인을 local bare remote로 먼저 검증한다. 이후 사용자 기록 저장소 URL·checkout·자동 push 허용 범위를 받아 연결한다. hooks/MCP/import/로그 용량 정책/작업 완료 명령은 후속 범위다.

## 실행용 래퍼: codex/execution-wrappers 브랜치

첫 구현: `run --wrapper`의 원문·SHA-256 보존, 임시 복사본 실행, 성공·실패·timeout·중단 시 소유한 폴더만 정리. 기존 명령·cwd 의미를 유지한다. CLI/Skill/개발 지침에서 일회성 래퍼와 재사용 도구를 구분한다. main 병합은 별도로 검토한다.

완료 기준: 입력 파일 및 대상 프로젝트 파일 보존, 실행 사본 제거, 실패 증거 유지, 동시 실행 분리, 기존 테스트 통과. 강제 종료 복구와 잔여 폴더 삭제는 이번 범위에 포함하지 않는다.
